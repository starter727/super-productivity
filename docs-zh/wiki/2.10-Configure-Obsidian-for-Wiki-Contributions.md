# 配置 Obsidian 以修改 Wiki

Obsidian 非常有用，但需要进行一些特定调整，以生成符合标准的 Markdown。

## Git 集成

1. 你必须使用 `super-productivity/docs` 中的 `wiki` 目录打开一个新仓库。新笔记将显示为 `super-productivity/docs/wiki/note.md`（笔记没有嵌套/子目录）。

2. 确保 Obsidian 数据不会泄漏到仓库中。对于仅本地排除，请使用：
   `echo ".obsidian" >> .git/info/exclude`

3. 确保每次提交前都进行 Markdown 代码检查。详情请参见 [[0.01-Style-Guide#Linting|样式指南#代码检查]]。

4. 不要使用"Git"插件。

## 设置（与默认不同）

### 编辑器

**严格行宽**
启用。
在预览模式下查看笔记时，它会正确显示 GitHub 如何渲染单行空格。你可以通过在行尾添加两个空格来创建单行空格。

**默认编辑模式**
源代码模式。
更好的设置是在一个窗格中使用源代码模式，在另一个窗格中链接预览，以帮助减少代码检查器会发现的问题数量。

**显示行号**
启用。
更容易看到空白字符的数量。

**使用制表符缩进**
禁用。
当此设置禁用时，"tab"键被硬编码为 4 个空格，因此需要手动输入 2 个空格（尤其是在嵌套列表时）。

### 文件和链接

**新附件的默认位置**
指定 `./assets` 目录。

**新链接格式**
来自仓库的路径将确保没有重复的笔记。

**自动更新内部链接**
启用。

## 插件

**Broken Links（失效链接）**
在提交前运行。

**Paste image rename（粘贴图片重命名）**
默认设置。
有助于保持图片命名一致。

**Linter（代码检查器）**
启用/设置 [[3.97-Obsidian-Linter-Config-MD|Obsidian Linter 配置 MD]] 中指示的规则，或导入 [[3.98-Obsidian-Linter-Config-YAML|Obsidian Linter 配置 YAML]] 中的 YML。

为匹配以下正则表达式的文件添加忽略规则：`^(_Sidebar|_Footer|Home)(\.md)?$`

**Safe Filename Linter（安全文件名检查器）**
将所有选项设置为"空字符串"。
在提交前对所有文件运行。
