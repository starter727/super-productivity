# 管理你的数据（Managing Your Data）

你在 Super Productivity 中的数据是应用存储的代表你工作的所有内容：任务（活动和已归档）、项目、标签、时间追踪、指标、笔记、提醒、配置等等。应用是**本地优先（local-first）**的：数据存在于你的设备上（或浏览器中），你控制它如何备份、导出、导入和同步。理解"你的数据"包括什么、导入和导出如何工作、备份如何创建以及同步和冲突如何处理，有助于你保持数据安全并在设备间移动或从问题中恢复。

关于数据存储在哪里、备份按平台放在哪里以及备份/导入/导出/同步的技术细节，参见 [[3.06-User-Data]]。关于如何从备份文件恢复，参见 [[2.02-Restore-Data-From-Backup]]。

## 你的数据包括什么

你的数据是应用状态的**完整快照**。它包括：

- **任务** —— 活动任务和已归档任务（近期和旧归档），带有所有属性和时间追踪数据。
- **项目和标签** —— 所有项目、标签及其设置。
- **时间追踪** —— 每个任务每天的���费时间、休息时间及相关状态。
- **配置** —— 全局设置、提醒、专注模式和休息提醒选项等。
- **笔记** —— 任务笔记和项目笔记。
- **指标** —— 每日指标、反思、影响度和精力评分、专注会话。
- **其他** —— 简单计数器、规划器和看板状态、任务重复配置、问题提供者设置、插件数据以及归档（近期和旧）。

完整的备份或导出中不会遗漏任何内容：当你导出或应用创建自动备份时，它包含以上所有内容（当包含归档时，包括近期和旧两个层级）。因此"你的数据"是应用在另一设备上或重新安装后恢复工作区所需的一切。

## 导入：导入数据

**导入**会用备份或导出文件中的数据替换你当前的应用数据。应用支持**完整备份格式**：一个包含（或包装）完整应用状态的 JSON 结构。较旧的遗留格式会被检测到但不再迁移；你会看到一条消息提示不支持迁移。

**验证和修复：** 应用在应用导入之前会**验证**数据（结构和关系，例如任务引用的项目和标签是否存在）。如果验证失败，它可能在可能时仍然**自动修复**数据——例如修复孤立任务、缺少的项目或标签引用，或不一致的列表——使你最终得到一个一致的状态，而不是导入失败。如果无法修复，导入会中止，你会收到错误。

**加密：** 如果备份已加密而你的应用未加密（或相反），应用会在导入前警告你并要求确认，因为导入会改变数据是否加密。

**导入的效果：** 导入**替换**当前状态。应用持久化导入的数据（包括将归档数据写入存储）并将其视为新的事实来源。你之前的状态不再活跃；只有通过导入更早的备份（如果你有）才能恢复它。

## 导出：获取快照

**导出**在你导出时生成数据**快照**。它不是"实时"视图：应用中当时的任何内容（如果你选择包含归档，则包括归档）都会被序列化到一个 JSON 文件中。你可以使用该文件作为备份、将其移到另一设备或归档。关系（例如任务 → 项目、任务 → 标签、子任务 → 父任务）通过 JSON 中的 **ID 引用**保留；导入时使用的验证和修复逻辑确保这些引用在文件稍后被导入时保持一致。

因此导出 = 现在保存所有内容；导入 = 从此文件加载所有内容并替换当前数据。

## 备份：自动和手动

**自动备份** —— 在设置中启用后，应用会按计划创建备份（例如每 5 分钟）。存储位置取决于平台：在**桌面端（Electron）**上，备份是用户数据文件夹中的带时间戳 JSON 文件（例如 ackups/ 目录），并自动清理旧文件。在 **Android** 和 **iOS** 上，备份存储在平台适合的存储中（例如 IndexedDB 或专用文件）。在 **Web 端**，没有基于文件的自动备份；你使用"导出数据"来下载文件。参见 [[3.06-User-Data]] 了解按平台的确切位置和行为。

**手动备份** —— 你可以通过以下方式触发备份：（1）在设置中使用**"创建手动备份"**，（2）依赖应用在某些同步操作前创建的**安全备份**（应用保留有限数量的近期和每日备份槽），或（3）使用**"导出数据"**下载备份文件。导出的文件可以稍后通过设置 → 导入/导出导入（参见 [[2.02-Restore-Data-From-Backup]]）。

**包含的内容：** 备份和导出包含**所有**应用数据；没有内容被排除。当包含归档时，近期和旧两个归档层级都是备份的一部分，因此你可以恢复完整历史记录。

## 同步：本地优先和冲突解决

应用使用**本地优先、基于操作的同步**：你的设备是主要副本；同步发送**更改**（操作）到远程端（或单个同步文件），而不是每次都上传整个数据集。这保持了同步快速和低带宽。支持多个**同步提供者**（例如 SuperSync 服务器（beta）、WebDAV、Dropbox、本地文件）；基于文件的提供者通常使用一个同步文件，包含状态快照加上近期操作。

**冲突** —— 当相同数据在两个地方被更改时（例如在两个设备上），在它们同步之前，应用检测到冲突。它自动使用**最后写入者获胜（last-write-wins）**解决大多数冲突：**较新时间戳**的更改被保留；如果时间戳相同，则**远程**（服务器）方胜出。当你的本地更改胜出时，应用创建新操作，以便你的版本被发送到远程。在某些情况下（例如首次同步时本地和远程都已���数据），应用可能要求你选择**使用本地**或**使用远程**，而不是应用自动解决。解决后，应用可以验证和修复状态，以便引用（例如任务到项目）保持一致。

因此在实际使用中：**较新者胜出**；你只在应用提示时选择（例如首次同步）。

## 总结

- **你的数据** = 完整应用状态（任务、项目、标签、时间、配置、笔记、指标、归档等）；备份和导出包含所有内容。
- **导入** = 用备份文件替换当前数据；数据在可能时被验证和修复；加密变化会收到警告。
- **导出** = 导出时的快照；关系通过 ID 保留；用于备份或传输。
- **备份** = 自动（启用时，位置取决于平台）和手动（手动按钮、安全备份、导出）；不排除任何数据。
- **同步** = 本地优先、基于操作；冲突通过较新者胜出解决（或在提示时由你选择）。
