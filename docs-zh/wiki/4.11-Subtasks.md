# 子任务（Subtasks）

Super Productivity 中的子任务让你可以将任务分解为更小的步骤，同时保持所有内容相互链接：每个子任务都是一个真实的任务，拥有自己的标题、时间追踪和完成状态，但它属于一个父任务。应用维护清晰的父子关系，使你可以展开和折叠层次结构，在父任务上查看汇总进度（例如剩余时间），并独立移动或完成子任务。理解子任务如何建模、存在哪些限制以及完成和移动如何工作，有助于你在项目、标签和今日视图中有效��用它们。

关于如何在 UI 中添加、重新排序、转换和管理子任务，参见 [[2.04-Manage-Subtasks]]。关于父任务和子任务链接如何融入任务模型，参见 [[4.09-Task-Attributes]]。

## 子任务如何建模

子任务是链接到父任务的**独立任务**，双向均可关联。它们不仅仅是父任务内的标签或行；每个子任务都拥有自己的 ID、项目、花费时间、笔记和完成状态，就像任何其他任务一样。区别在于关系：

- **子任务（child）** 存储对其父任务的引用。正是这个链接使其成为子任务而非顶层任务。
- **父任务（parent）** 存储其子任务 ID 的有序列表。该列表中的顺序就是你展开父任务时看到的顺序。

因为关系的两端都被存储，应用可以快速显示父任务的子任务列表，在你完成或移动子任务时更新父任务，并在你重新组织时保持层次结构一致。当你添加子任务、将其移到另一个父任务或删除父任务时，应用会同时更新子任务的父引用和父任务的子任务列表，使它们始终匹配。

子任务本身也可以有子任务（嵌套）：一个任务可以同时是父任务和子任务。相同的双向链接在每个层级都适用。在实践中，非常深的嵌套在 UI 中可能更难操作，在某些工作流中（例如基于 Markdown 的同步）深层级别可能被不同处理；应用的设计使得一或两个层级的子任务为常见情况。

## 子任务的限制

并非每个任务都可以变成子任务，并且某些行为受到约束以保持模型一致性。

### 不能转换为子任务的任务

两种类型的任务**不能**转换为子任务：

- **重复任务** —— 按计划（例如每天或每周）重复的任务不能成为另一个任务的子任务。参见 [[4.13-Repeating-Tasks]]。重复规则应用于单个任务；嵌套会与之冲突。
- **问题链接任务** —— 链接到外部问题（例如 Jira 或 GitHub）的任务不能成为子任务。问题链接是任务和问题之间的一对一关系；应用不支持以相同方式处理问题链接的子任务。

如果你尝试将此类任务转换为子任务（例如通过在基于 Markdown 的工作流中缩进），应用会���告你并将任务保留为顶层任务。你仍然可以在父任务下创建普通子任务，并将重复或问题链接的任务作为独立任务并列使用。

### 基于 Markdown 的工作流中的深度和嵌套

当你使用基于 Markdown 的工作流（例如 sync-md 插件）将缩进转换为父子结构时，深度由缩进级别决定。非常深的缩进可能被解释为笔记内容或不同层级的嵌套，而非额外的子任务层级。如果你依赖 Markdown 导入/导出，建议将嵌套保持在一到两个层级，以便结构按预期保留。

### 移动或复制时的继承和一致性

- **项目继承** —— 每个任务，包括每个子任务，恰好属于一个项目。当你**将子任务移动到不同的父任务**时，子任务继承**新父任务的项目**。这使子任务保持在正确的项目中，无需你手动更改项目。如果���将其移回另一个不同项目的父任务，它将相应地继承该父任务的项目。
- **复制** —— 当你**复制一个带有子任务的任务**时，应用复制**整个层级结构**：父任务及其所有子任务，带有新的 ID 和相同的父子链接。复制的子任务保持在复制的父任务下，因此你得到结构的完整副本。

## 完成行为

父任务和子任务的完成方式会影响你如何跟踪进度以及删除或归档时会发生什么。

### 独立完成

子任务可以**独立标记为完成**。你可以在父任务之前或之后完成子任务：例如，你可能完成所有子任务然后标记父任务完成，或者先标记父任务完成并留下一些子任务稍后完成。应用不强制固定的顺序。父任务的完成状态是独立的；通常当所有子任务完成时父任务被视为"完成"，但你可以覆盖它，如果想的话可以提前完成父任务。时间追踪和剩余时间聚合（估算减去花费时间）按每个子任务进行，并从子任务汇总到父任务，因此父任务的"剩余工作"反映了其子任务剩余时间的总和。

### 级联删除

当你**删除父任务**时，应用也会**删除其所有子任务**。系统不会提示你逐个删除它们；父任务及其子任务一起被移除。这避免了留下孤立的子任务，并保持任务列表一致。如果你只想移除父任务但保留工作，你可以在删除父任务之前将子任务移动到另一个父任务（或将其转换为顶层任务，如果你的工作流支持）。

### 标签视图中的标签和父子关系

标签视图（参见 [[4.07-Tag-View]]）显示具有给定标签的任务。为避免显示相同的工作两次并保持列表可管理，当你**将子任务添加到标签**时，应用会**从该标签中移除父任务**。因此，标签视图在该标签中显示父任务或��子任务，而不是两者。这样你在标签中看到任务的一个层级，避免重复或令人困惑的条目。如果你希望父任务和子任务都在一个标签中，此模式不受支持；应用强制标签视图中为"一个层级"以保持一致。

## 移动和重新组织

你可以**将子任务移动到另一个父任务**（或通过移除其父引用使其成为顶层任务）。当你这样做时：

- **旧父任务的子任务列表**会更新：移动的子任务从其中移除。
- **新父任务的子任务列表**会更新：移动的子任务被添加到其中（在 UI 允许的情况下，位于你选择的位置）。
- **子任务的父引用**会更新为新父任务。
- **子任务的项目**设置��新父任务的项目，如上所述。

这些更新同时发生，使得移动完成后层次结构保持一致：没有子任务出现在两个父任务的列表中，并且每个子任务恰好指向一个父任务。在同一个父任务内重新排序子任务只会更改父任务的子任务列表顺序；不会更改父引用或项目。

## 子任务出现的位置

子任务在任务列���中出现在**其父任务之下**：在项目视图、标签视图、今日视图等地方。你通常可以展开和折叠父任务以显示或隐藏其子任务。在任务详情面板中，当你打开父任务时，你可以查看和编辑其子任务列表，并打开单个子任务。父任务和子任务属性（包括时间估算和花费时间）由 [[4.04-Schedule-View]] 和 [[4.08-Time-Estimates]] 使用，以便父任务的剩余工作和时间线在适用时反映其子任务的总和。
