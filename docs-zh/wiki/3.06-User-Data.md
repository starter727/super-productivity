# 用户数据

**用户数据**的概念**仅适用于桌面版（Electron）应用**。Web 应用将数据存储在浏览器存储（IndexedDB 和 localStorage）中。关于 Web 与桌面版的差异，请参见 [[3.05-Web-App-vs-Desktop|Web 应用与桌面版对比]]。关于导入、导出、备份和同步从用户角度如何工作的概述，请参见 [[4.23-Managing-Your-Data|管理你的数据]]。

## 包含的数据

完整备份或导出包含所有应用数据：任务（活动和已归档）、项目、标签、时间追踪状态、全局配置、笔记、提醒、指标、简单计数器、计划和白板状态、任务重复配置、问题提供商设置、插件用户数据，以及两个归档层级（近期和旧归档）。完整备份或导出不排除任何数据。

## 用户数据文件夹的用途

用户数据文件夹是桌面应用用来存储以下内容的应用数据目录：

- 所有用户数据、设置和配置
- 自动备份
- 自定义主题文件（`styles.css`）
- IndexedDB 和 localStorage 数据（由 Electron 管理）

## 各平台的默认位置

| 平台        | 位置                                                                                     |
| ----------- | ---------------------------------------------------------------------------------------- |
| **macOS**   | `~/Library/Application Support/superProductivity/`                                       |
| **Windows** | `C:\Users\<YOUR_USER_NAME>\AppData\Roaming\superProductivity/` 或 `%APPDATA%\superProductivity` |
| **Linux**   | `~/.config/superProductivity/`                                                           |

备份路径在 UI 的设置 → 自动备份中显示（包括 `backups/` 子文件夹），并且在从命令行启动应用时会打印出来。

### 自定义文件夹位置

你可以使用 `--user-data-dir` 命令行参数指定自定义的用户数据目录：

```bash
superproductivity --user-data-dir=/path/to/my/data
```

尾部斜杠会被去除。该会话中将使用自定义路径替代默认路径。

### Snap 包（Linux）

对于 Linux 上的 Snap 包，应用使用 `SNAP_USER_COMMON` 目录，以确保数据不会被 Snap 更新进程访问。有效路径为 `$SNAP_USER_COMMON/.config/superProductivity`（或应用名称的等效路径）。

### Windows 应用商店

Windows 应用商店构建使用不同的路径，包含 Windows 应用商店包标识符（位于 `Local\Packages\...\LocalCache\Roaming` 而不是 `Roaming`）。

## 目录结构

### backups/ 子目录

- 存储自动备份文件（JSON）。
- 位置：`{userData}/backups/`。
- 在桌面版上，自动备份文件使用文件名格式 `YYYY-MM-DD_HHmmss.json`。

### styles.css（可选）

- 用于桌面版样式的自定义主题文件。
- 必须由用户手动创建，并直接放置在用户数据文件夹中（不在子文件夹中）。
- 由主进程加载并注入到渲染进程中；无效的 CSS 可能加载失败并记录日志。

### IndexedDB 和 localStorage（Electron 管理）

- IndexedDB 数据库和 localStorage 条目位于 userData 路径下特定于平台的位置。
- 由 Electron 管理；不要手动移动或编辑这些文件。

## 文件类型和格式

### JSON 备份文件

- **格式：** 桌面版自动备份使用 `YYYY-MM-DD_HHmmss.json`。
- **内容：** 完整的应用状态序列化为 JSON。
- **命名：** 按本地日期和时间添加时间戳（例如 `2025-01-15_143022.json`）。

### CSS 主题文件

- **文件：** `styles.css`（需使用确切名称）。
- **用途：** 用于主题的自定义 CSS；由用户创建，可选。

### IndexedDB 数据库

- **SUP_OPS**（当前，版本 4）：主数据库。对象存储：`ops`、`state_cache`、`import_backup`、`vector_clock`、`archive_young`、`archive_old`。保存操作日志、状态快照、向量时钟和归档。
- **pf：** 用于迁移和恢复的传统数据库。
- **SUPPluginCache：** 插件缓存。

### localStorage 键

UI 和应用状态存储的键包括：

- `SUP_UI_HELPER`、`SUP_ACTION_LOG`、`SUP_LAST_ERROR_ACTION_LOG`
- `SUP_IS_PROJECT_LIST_EXPANDED`、`SUP_IS_TAG_LIST_EXPANDED`
- `DARK_MODE`、`SUP_NAV_SIDEBAR_EXPANDED`、`SUP_NAV_SIDEBAR_WIDTH`、`SUP_RIGHT_PANEL_WIDTH`
- `SUP_IS_ADD_TO_BOTTOM` 等（完整列表请参见 `storage-keys.const.ts`）。

## 备份行为

**自动备份：** 在设置中启用后，应用会按计划创建备份（默认：每 5 分钟）。该设置仅为开/关；间隔和备份子目录在 UI 中不可配置。存储位置取决于平台：

| 平台                     | 自动备份的存储位置                                   |
| ------------------------ | ---------------------------------------------------- |
| **Electron（桌面版）**   | `{userData}/backups/YYYY-MM-DD_HHmmss.json`          |
| **Web 应用**             | 浏览器开发者工具 → 存储 → IndexedDB → SUP_OPS → import_backup |
| **Android**              | Android 文件系统中的应用本地存储                     |

## 导入和导出

**导出：** 设置 → 同步与备份 → 导入/导出 → 导出到文件。在 Electron/桌面版上，这会打开原生保存对话框。在 Web 应用上，它会下载一个 JSON 文件。导出的数据是完整应用状态的序列化 JSON，包括任务、项目、配置、归档和所有其他数据。

**导入：** 设置 → 同步与备份 → 导入/导出 → 从文件导入。这会在导入前显示**确认对话框**。导入后，当前状态被替换；归档数据写入 IndexedDB。关于如何执行恢复，请参见 [[2.02-Restore-Data-From-Backup|从备份恢复数据]]。

## 同步

**策略：** 应用使用**本地优先、基于操作**的同步。本地设备是数据源；同步每次交换的是**操作**（变更）而不是完整的状态文件。这减少了负载大小，并支持实体级别的冲突检测。

**提供商：** 支持四个同步提供商：**SuperSync**（基于服务器的操作同步；非常新，仍处于 beta 阶段）、**WebDAV**（基于文件）、**Dropbox**（基于文件）和**本地文件**（基于文件，Electron/Android）。基于文件的提供商存储一个单一的同步文件（例如 `sync-data.json`），其中包含完整的状态快照以及最近操作的缓冲区和用于因果关系的向量时钟。

**冲突解决：** 使用向量时钟检测冲突（同一实体在同步前在两个地方被更改）。解决方式为**最后写入者胜出（LWW）**：具有**较新时间戳**的操作胜出；如果时间戳相等，**远程**（服务器）端胜出。当本地胜出时，应用会创建一个新的更新操作，以便在下次同步时传播本地状态。**相同的冲突**（例如双方都删除了同一实体或进行了相同的更改）会自动解决，无需用户操作。在**首次同步**情况下，如果本地和远程都已存在数据，应用可能会显示一个对话框，让你选择**使用本地**或**使用远程**。解决后，状态会根据需要进行验证和修复。

## 用户可编辑的系统管理

**用户可编辑：**

- **styles.css** —— 创建和编辑以进行自定义主题。
- **备份文件** —— 可以通过设置 → 同步与导出 → 导入/导出 → 从文件导入进行恢复（参见 [[2.02-Restore-Data-From-Backup|从备份恢复数据]]）。

**系统管理（不要手动编辑）：**

- IndexedDB 数据库。
- localStorage 条目。
- 活动备份文件（可作为 JSON 读取，但不建议手动编辑）。

## 大小限制和配额

### 客户端 IndexedDB

- 当发生 `QuotaExceededError` 时，应用会触发紧急压缩（保留 24 小时而不是 7 天），并使用断路器避免无限重试。
- 浏览器/操作系统配额和可用磁盘空间适用。

### SuperSync 服务器（如果使用；beta 版）

- 默认配额：每个用户 100 MB。
- 超出配额时自动清理。

## 权限

- 应用需要对用户数据文件夹进行正常的读/写访问。默认位置位于用户的主目录或应用数据目录下；不需要管理员/root 权限。
- 需要文件系统访问的插件需要 `nodeExecution` 权限和用户明确同意。

## 恢复和修复

### 自动数据修复

- 验证在操作生命周期的多个点运行。
- 修复诸如孤立任务、无效引用和不一致关系等问题；为日志创建 `REPAIR` 操作。

### 灾难恢复

- 如果主数据库（`SUP_OPS`）丢失或损坏，应用会尝试从传统的 `pf` 数据库加载并运行初始迁移。
- 如果恢复失败，需要完全的重新同步（或从备份恢复）。

### 备份恢复

- 通过设置 → 同步与导出 → 导入/导出 → 从文件导入，从 `backups/` 中的备份文件恢复。请参见 [[2.02-Restore-Data-From-Backup|从备份恢复数据]]。

### 同步状态损坏

- 当由于缺少依赖项而无法应用操作时，应用会抛出 `SyncStateCorruptedError`，并期望通过完全重新同步来恢复一致状态。

## 配置和版本控制

- 用户数据文件夹中没有单独的配置文件。配置存储在 IndexedDB（`SUP_OPS`、`state_cache`）和 localStorage（`SUP_*` 及相关键）中。
- **数据库版本：** `SUP_OPS` 的模式版本为 4。
- **应用版本：** 在构建中定义（例如 `src/environments/versions.ts`），不存储在用户数据文件夹中。
- **备份文件：** 每个 JSON 文件携带完整状态；桌面版自动备份命名包含日期和时间。

## 应用访问（桌面版）

- **主进程：** 通过 Electron `app.getPath('userData')` 获取路径；当使用 `--user-data-dir` 或 Snap 逻辑时，使用 `app.setPath('userData', path)` 设置自定义路径。
- **渲染进程：** 通过 IPC 暴露路径（例如 `getUserDataPath()`）。
- **备份和文件同步：** 使用 Node.js `fs` API（例如 `readFileSync`、`writeFileSync`、`readdirSync`、`statSync`、`unlinkSync`）进行备份和本地文件同步。

## 说明

- **Web 应用：** 数据仅存在于浏览器存储中；没有用户数据文件夹。请参见 [[3.05-Web-App-vs-Desktop|Web 应用与桌面版对比]]。
- **自定义 WebDAV 同步：** 作为内置同步的替代方案，你可以使用外部 WebDAV 或云同步工具同步用户数据文件夹的内容。
- **主题：** 示例主题和主题创建指南：[super-productivity-themes](https://github.com/super-productivity/super-productivity-themes)。
