# 样式指南

本文概述了这些 Markdown 笔记所采用的一些结构和格式选择。在 CommonMark、GitHub Flavored Markdown、GitHub 内置 Wiki 限制和 Obsidian Flavored Markdown 之间保持兼容性需要刻意努力，否则它们可能无法相对容易地移植到其他服务（例如其他 Wiki 程序、通过静态站点生成器的 GitHub/Cloudflare Pages 等）。

以下许多限制（尤其是路径和命名）是由于 GitHub 的 Wiki 对其接收的笔记进行清理和重组的方式所致。

另请参见：[[0.-Meta-Diataxis|元文档框架]] 了解所使用的文档框架介绍，以及 [[0.00-Wiki-Structure-and-Organization|Wiki 结构与组织]] 了解有关如何为 Wiki 编写笔记的更多详情。

## 扁平结构与绝对路径

嵌套目录仅在使用 Wiki 风格链接时才可靠。如果不同子目录中存在重复的笔记名称，则无法阻止 GitHub 将 `Dir1/note.md` 和 `Dir2/note.md` 合并为单个笔记，而另一个将变得无法访问。

因此：所有笔记应位于 `docs/wiki` 内部的"扁平"结构中，图像和其他文件可以放在子目录中，因为 GitHub 不需要将它们渲染为单独的页面。将内容存储在 `docs/wiki/assets` 中有助于保持 `docs/wiki` 根目录更整洁。

```txt
vault/
├── 1.01-First-Steps.md
├── 2.09-Configure-Sync-Backend.md
├── ...
├── assets/
│   ├── 1.01-First-Steps-start-time-tracking.png
│   ├── diagrams/
│   │   └── flow.png
│   └── ...
└── ...
```

## Wiki 风格链接

Markdown 链接对于其他人来说冗长且输入不便。如果链接是自动生成的，那就不是问题。因此对笔记和图像强制使用 Wiki 风格链接。GitHub 和 Obsidian 之间唯一的显著区别是 GitHub 不需要使用 `!`。

以下两者都有效：
根目录：`[[image-at-root.png]]`
嵌套图像：`[[images/image.png]]`

如上所述，嵌套图像可以减少杂乱，因此更推荐。

### 别名

诸如 `[[9.Test-Note|Test Note]]` 之类的链接会导致路径被渲染为诸如 `../wiki/Test-Note` 的 URL，并且无法解析到任何内容。请勿使用此语法。

## 代码检查（Linting）

存在一个 GitHub Action，使用 `pymarkdownlnt` 对所有 Markdown 进行代码检查。如果可能，在提交 PR 之前对 `./docs/wiki` 下的所有文件运行 `pymarkdownlnt --disable-rules line-length scan --recurse ./docs/wiki`。在 Arch 上只需 `pipx install pymarkdownlnt`。理想情况下，将其配置为 pre-commit 钩子，以确保每次提交都能通过 CI。

这个简单的钩子应该足够了：

```md
cat > .git/hooks/pre-commit <<'EOF'
#!/bin/sh
set -eu

pymarkdownlnt --disable-rules line-length scan "docs/wiki"
EOF

chmod +x .git/hooks/pre-commit
```

### 将特定笔记排除在 H1 规则之外

代码检查规则 **MD041**（文件第一行应为顶级标题）可以对特定笔记禁用，这样它们就不必以 H1 开头。

**逐笔记禁用：** 将此 HTML 注释作为笔记的**第一行**添加（前面不要有空行）：

```md
<!-- pyml disable md041 -->
```

该 pragma 在解析前会被去除，因此不影响渲染。只有该文件不受 MD041 约束。

**整个 Wiki：** 要关闭所有 Wiki 笔记的 H1 要求，将 `md041` 添加到 `.github/workflows/wiki-sync.yml` 的 `--disable-rules` 列表中（例如 `--disable-rules line-length,no-inline-html,md041`）。无需逐笔记添加 pragma。

可以使用安装了"Linter"插件的 Obsidian 进行额外的代码检查。详情请参见 [[2.10-Configure-Obsidian-for-Wiki-Contributions#Plugins|配置 Obsidian 以贡献 Wiki]]。

## 缩进

不使用制表符。

仅使用两个空格。

## 空格和连字符

在 Obsidian 中将所有空格替换为连字符。GitHub 会自动执行此操作，最好有意识地这样做，以避免潜在的笔记冲突，例如 `API Reference.md` 和 `API-Reference.md`。如果被 GitHub 检测到，其中一个将被静默丢弃或至少无法通过常规链接访问。

## 锚点链接

与笔记类似，它们在单个笔记内是扁平的。空格变为连字符，大写也变为小写。如果试图为每个子标题维护唯一的扁平引用，笔记会变得非常难看。如果有办法验证标题以防止重复，那会容易一些。谨慎使用，并优先保持笔记简短，以完全避免需要深层嵌套引用。
