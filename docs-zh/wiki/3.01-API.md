# API

本参考文档是使用 Super Productivity API 的入口。应用公开**三个 API 系统**：**同步服务器 REST API**（用于数据同步）、**本地 REST API**（用于从本地脚本控制桌面应用）和**插件 API**（用于扩展应用）。本参考总结了所有三个 API；完整的请求/响应模式和示例位于仓库中（同步服务器：`packages/super-sync-server/`；插件 API：`packages/plugin-api/` 和 `docs/plugin-development.md`；本地 REST API：`src/app/core/electron/local-rest-api-handler.service.ts`）。

## 1. 同步服务器 REST API

同步服务器是一个自定义的、基于操作的同步服务（事件溯源风格）。它**不是** WebDAV。它旨在与内置的 SuperSync 同步提供商一起使用。SuperSync 非常新，仍处于 beta 阶段。关于面向用户的同步选项，请参见 [[2.08-Choose-Sync-Backend|选择同步后端]] 和 [[2.09-Configure-Sync-Backend|配置同步后端]]。

### 认证与授权

所有同步端点需要 **JWT Bearer** 认证：`Authorization: Bearer <token>`。

- **令牌过期时间：** 7 天。
- **环境：** 服务器需要 `JWT_SECRET`（最少 32 个字符）。
- **令牌内容：** `userId`、`email`、`tokenVersion`（用于失效处理）。
- 无效或缺失令牌返回 401。

### 认证端点

**传统方式：**

- `POST /api/register` —— 用户注册（需要邮箱验证）。
- `POST /api/login` —— 密码登录。
- `POST /api/verify-email` —— 邮箱验证。
- `POST /api/replace-token` —— 替换被盗用的 JWT（需要当前认证）。

**通行密钥 (WebAuthn)：**

- `POST /api/register/passkey/options` —— 注册选项。
- `POST /api/register/passkey/verify` —— 验证注册。
- `POST /api/login/passkey/options` —— 认证选项。
- `POST /api/login/passkey/verify` —— 验证认证。
- `POST /api/recover/passkey` —— 请求通行密钥恢复（例如魔法链接）。
- `POST /api/recover/passkey/options` —— 恢复注册选项。
- `POST /api/recover/passkey/complete` —— 完成恢复。

**魔法链接：**

- `POST /api/login/magic-link` —— 请求魔法链接邮件。
- `POST /api/login/magic-link/verify` —— 验证魔法链接令牌。

**账户：**

- `DELETE /api/account` —— 删除用户及其所有数据（需要认证）。

### 同步端点

所有端点需要认证。

**操作：**

- `POST /api/sync/ops` —— 上传操作（增量）。请求体：`ops[]`、`clientId`、可选 `lastKnownServerSeq`、可选 `requestId`（去重）。
- `GET /api/sync/ops?sinceSeq={seq}&limit={limit}&excludeClient={clientId}` —— 下载操作。查询参数：`sinceSeq`（必填）、`limit`（默认 500，最大 1000）、`excludeClient`（可选）。

**快照：**

- `GET /api/sync/snapshot` —— 获取完整状态快照。
- `POST /api/sync/snapshot` —— 上传完整状态（备份/修复/迁移）。请求体限制 30 MB（压缩后）。

**状态与维护：**

- `GET /api/sync/status` —— 同步状态和存储信息。
- `DELETE /api/sync/data` —— 删除用户的所有同步数据（例如加密密码更改）。
- `GET /api/sync/restore-points?limit={limit}` —— 列出恢复点（限制 1–100）。
- `GET /api/sync/restore/{serverSeq}` —— 获取特定序列处的状态快照。

**健康检查：**

- `GET /health` —— 数据库连接检查（无需认证）。成功返回 200，附带 `{ status: 'ok', db: 'connected' }`；失败返回 503。

### 请求/响应概述

- **上传操作：** 请求体是操作数组；每个操作有 `id`、`clientId`、`actionType`、`opType`、`entityType`、`entityId`/`entityIds`、`payload`、`vectorClock`、`timestamp`、`schemaVersion`、可选 `isPayloadEncrypted`。响应：`results[]`（每个操作的 accepted/rejected + `serverSeq`）、可选 `newOps`、`latestSeq`、可选 `hasMorePiggyback`、可选 `deduplicated`。
- **下载操作：** 响应：`ops`、`hasMore`、`latestSeq`、可选 `gapDetected`、可选 `latestSnapshotSeq`、可选 `snapshotVectorClock`、`serverTime`。
- **快照：** 响应：`state`、`serverSeq`、`generatedAt`。上传快照请求体：`state`、`clientId`、`reason`、`vectorClock`、`schemaVersion`、可选 `isPayloadEncrypted`。
- **状态：** 响应：`latestSeq`、`devicesOnline`、可选 `snapshotAge`、`storageUsedBytes`、`storageQuotaBytes`。

精确模式（服务器端的 Zod，仓库中的 TypeScript 类型）位于 `packages/super-sync-server/src/sync/sync.types.ts` 和 `sync.routes.ts` 中。

### 错误代码

结构化的错误代码（供客户端处理）包括：`VALIDATION_FAILED`、`INVALID_OP_ID`、`INVALID_OP_TYPE`、`INVALID_ENTITY_TYPE`、`INVALID_ENTITY_ID`、`INVALID_PAYLOAD`、`PAYLOAD_TOO_LARGE`、`INVALID_VECTOR_CLOCK`、`INVALID_CLIENT_ID`、`CONFLICT_CONCURRENT`、`CONFLICT_SUPERSEDED`、`DUPLICATE_OPERATION`、`RATE_LIMITED`、`STORAGE_QUOTA_EXCEEDED`、`ENCRYPTED_OPS_NOT_SUPPORTED`、`SYNC_IMPORT_EXISTS`、`INTERNAL_ERROR`。定义在 `sync.types.ts`（`SYNC_ERR_*` 常量）中。

### 速率限制（按端点）

- **认证：** 登录/注册端点限制为每分钟 6 次请求。
- **同步上传：** `POST /api/sync/ops` 限制为每分钟 30 次请求（每个用户）。
- **同步下载：** `GET /api/sync/ops` 限制为每分钟 60 次请求（每个用户）。
- **快照：** `GET /api/sync/snapshot` 限制为每分钟 10 次请求。
- **上传限制：** 最大载荷 20 MB；每次上传最大操作数 100。压缩操作体：10 MB；压缩快照：30 MB；解压上限（zip-bomb 防护）：100 MB。

### 压缩

- **请求：** 通过 `Content-Encoding: gzip` 进行 Gzip 压缩。Android 可以发送 base64 编码的 gzip，配合 `Content-Transfer-Encoding: base64`。
- **响应：** 服务器可以在配置的地方发送压缩响应。

### CORS

通过环境/配置进行配置。典型的允许头信息包括 `Authorization`、`Content-Type`、`Content-Encoding`、`X-Expected-Rev`、`X-Force-Overwrite`、`X-Requested-With`。支持凭证。

### 数据保留

操作、设备和相关验证数据保留 **45 天**。更旧的数据会被清除。

### 请求去重

上传操作接受可选的 `requestId`。使用相同 `requestId` 的重复请求会收到缓存的结果（以及适用时的新附带操作），因此客户端可以安全重试而不会重复操作。

### 端到端加密

载荷可以在客户端加密；服务器将其存储为不透明块。操作加密时不支持按序列恢复（`ENCRYPTED_OPS_NOT_SUPPORTED`）。

## 2. 插件 API

插件 API 是一个基于事件的系统，允许 JavaScript 插件运行自定义 UI、注册自定义快捷键、钩子和脚本，并与应用功能交互（例如启动计时器、添加任务）。插件在沙箱中运行。插件 API 的类型定义在 `packages/plugin-api/` 中。有关完整文档和示例，请参见仓库中的 `docs/plugin-development.md`。

### 认证

插件**不**直接访问同步服务器。插件 API 本身不需要认证；插件在应用上下文中运行，没有直接的网络级 API 访问。插件如果实现 `nodeExecution` 并包含自定义 Node.js 后端脚本，则必须在其清单中声明所需的权限，并且用户必须明确同意。

### 端点/事件

插件通过 `registerHook()`、`registerShortcut()`、`registerHeaderButton()` 等 API 方法向其注册的挂钩和 UI 元素发送数据。没有公开的 HTTP 端点。可用方法（在 `packages/plugin-api/src/types.ts` 中定义）：

- `registerHeaderButton(config, onClick)` —— 在应用标题栏添加一个图标按钮。
- `registerMenuEntry(config, onClick)` —— 在应用菜单中添加一个条目。
- `registerSidePanelButton(config, onClick)` —— 在侧面板中添加一个按钮。
- `registerShortcut(config, handler)` —— 注册自定义键盘快捷键。
- `registerHook(hook, handler)` —— 注册一个事件钩子（例如 `onTaskComplete`、`onStartTimeTracking` 等）。参见 `docs/plugin-development.md` 获取钩子列表。
- `execNodeScript(script, args)` —— 在 Node.js 后端（仅桌面版）执行自定义脚本。需要 `nodeExecution` 权限。
- `showNotification(title, text)` —— 显示原生通知。
- `showDialog(config)` —— 显示自定义对话框。
- `setInterval(handler, ms)` —— 设置间隔计时器。
- `setTimeout(handler, ms)` —— 设置超时计时器。

其他方法包括：`addTask`、`getTasks`、`getCurrentTask`、`getTaskById`、`getTasksByProject`、`openTask`、`getProjects`、`getProjectById`、`addProject`、`getTags`、`addTag`、`getSimpleCounters`、`addSimpleCounter`、`setSimpleCounterValue`、`updateGlobalConfig`、`getGlobalConfig`、`getGlobalConfigValue`、`getInitialData`。

完整的参考文档在 `docs/plugin-development.md#api-reference` 中（在仓库中）。

### 插件 API 分类

**数据 — 任务：**

- `getTasks()`、`getArchivedTasks()`、`getCurrentContextTasks()` — 读取任务。
- `addTask(taskData)`、`updateTask(taskId, updates)`、`deleteTask(taskId)` — 创建/更新/删除。
- `batchUpdateForProject(request)` — 对项目进行批量创建/更新/删除/重新排序。
- `reorderTasks(taskIds, contextId, contextType)` — 重新排序任务。

**数据 — 项目：**

- `getAllProjects()`、`addProject(projectData)`、`updateProject(projectId, updates)`。

**数据 — 标签：**

- `getAllTags()`、`addTag(tagData)`、`updateTag(tagId, updates)`。

**数据 — 简单计数器：**

- `setCounter(id, value)`、`getCounter(id)`、`incrementCounter(id, incrementBy)`、`decrementCounter(id, decrementBy)`、`deleteCounter(id)`、`getAllCounters()`。

**UI：**

- `showSnack(snackCfg)`、`notify(notifyCfg)` — 通知。
- `openDialog(dialogCfg)`、`showIndexHtmlAsView()` — 对话框和插件 UI。

**注册（仅主插件上下文；iframe 中不可用）：**

- `registerHeaderButton(config)`、`registerMenuEntry(config)`、`registerShortcut(config)`、`registerSidePanelButton(config)`、`registerHook(hook, handler)`。

**持久化：**

- `persistDataSynced(dataStr)`、`loadSyncedData()`、`getConfig()` — 插件特定的存储和配置。

**高级：**

- `executeNodeScript(request)` — 运行 Node.js 脚本（仅 Electron，需要 `nodeExecution` 权限和用户同意）。
- `dispatchAction(action)` — 派发 NgRx action（允许的子集）。
- `downloadFile(filename, data)`、`isWindowFocused()`、`onWindowFocusChange(handler)`。

### 钩子（事件）

插件可以为以下事件注册处理程序：`taskCreated`、`taskComplete`、`taskUpdate`、`taskDelete`、`currentTaskChange`、`finishDay`、`languageChange`、`persistedDataChanged`、`action`、`anyTaskUpdate`、`projectListUpdate`。载荷类型在 `plugin-api` 类型中定义（`HookPayloadMap`）。

`persistedDataChanged` 在初始启动加载后，对该插件持久化数据的任何更改（本地写入、远程同步、批量导入）触发。载荷为 `void`；重新调用 `loadSyncedData(key?)` 以获取最新数据。注册时不重放，快速更改不保证排序 — 处理程序必须是幂等的。

### 插件数据类型

核心类型（Task、Project、Tag、ProjectFolder 等）和批量类型（`BatchUpdateRequest`、`BatchUpdateResult`、`BatchOperation` 等）位于 `packages/plugin-api/src/types.ts`。

### 插件清单

插件需要 `manifest.json`：`name`、`id`、`manifestVersion`、`version`、`minSupVersion`，可选 `description`、`hooks`、`permissions`，可选 `iFrame`、`isSkipMenuEntry`、`type`、`assets`、`icon`、`nodeScriptConfig`、`sidePanel`、`jsonSchemaCfg`。参见仓库中的 `PluginManifest`。

### 插件权限

- **nodeExecution：** 使用 `executeNodeScript()` 所必需（仅 Electron；需用户同意）。参见 [[3.05-Web-App-vs-Desktop|Web 应用与桌面版对比]] 和 [[3.06-User-Data|用户数据]] 了解文件系统和仅桌面版行为。
- 其他权限可能限制特定的 API 方法；参见插件开发指南。

### Iframe 限制

当插件使用 iframe UI 时，以下功能**不可用**：`registerHeaderButton`、`registerMenuEntry`、`registerSidePanelButton`、`registerShortcut`、`registerHook`、`execNodeScript`。Iframe 内容受 CSP 约束（例如不能加载外部脚本；仅允许同源或内联）。

## 3. 本地 REST API（仅限 Electron/桌面版）

本地 REST API 是一个仅限本地主机的 HTTP 服务器，用于从本地脚本和进程控制桌面应用。**它仅适用于 Electron 桌面应用**，在 Web 应用或 Android 上不可用。默认禁用，在**设置 → 杂项 → 启用本地 REST API**中启用。

对于开发脚本，`SP_FORCE_LOCAL_REST_API=1 npm start` 在不更改持久化用户设置的情况下启动本地 REST API。此覆盖仅在 `NODE_ENV=DEV` 中有效。

### 前置条件

- **仅 Electron 桌面应用**（Web 或移动端不可用）
- 必须在设置中启用，除非使用开发覆盖
- 应用必须运行且渲染器就绪

### 认证

本地 REST API **不**使用认证。它绑定到 `127.0.0.1:3876`，仅接受来自本地主机的连接。**不要**将其暴露到外部网络。

### 基础 URL

```text
http://127.0.0.1:3876
```

### 响应格式

所有响应均为 JSON，使用一致的封装：

```typescript
// 成功
{ "ok": true, "data": <响应数据> }

// 错误
{ "ok": false, "error": { "code": "<ERROR_CODE>", "message": "<描述>" } }
```

### 健康检查

| 方法 | 路径      | 描述                           |
| ---- | --------- | ------------------------------ |
| GET  | `/health` | 检查服务器是否运行且渲染器就绪 |

**响应：**

```json
{ "ok": true, "data": { "server": "up", "rendererReady": true } }
```

### 通用端点

| 方法 | 路径        | 描述                   |
| ---- | ----------- | ---------------------- |
| GET  | `/status`   | 获取当前任务和任务计数 |
| GET  | `/projects` | 列出项目               |
| GET  | `/tasks`    | 列出任务               |
| GET  | `/tags`     | 列出标签               |

**GET /status 响应：**

```json
{
  "taskCount": 42,
  "currentTaskId": "abc123"
}
```

### 任务端点

| 方法   | 路径                    | 描述             |
| ------ | ----------------------- | ---------------- |
| GET    | `/tasks`                | 列出任务         |
| GET    | `/tasks/:id`            | 通过 ID 获取任务 |
| POST   | `/tasks`                | 创建新任务       |
| PATCH  | `/tasks/:id`            | 更新任务字段     |
| DELETE | `/tasks/:id`            | 删除任务         |
| GET    | `/tasks/:id/subtasks`   | 获取子任务       |
| POST   | `/tasks/:id/subtasks`   | 添加子任务       |
| POST   | `/tasks/:id/time-spent` | 添加时间记录     |

**GET /tasks 查询参数：**

| 参数      | 类型   | 描述                                     |
| --------- | ------ | ---------------------------------------- |
| `query`   | string | 按标题过滤（不区分大小写，包含匹配）     |
| `project` | string | 按项目 ID 过滤                           |
| `done`    | bool   | 包含已完成任务（默认 false）             |
| `tag`     | string | 按标签 ID 过滤                           |
| `limit`   | int    | 返回的任务数量上限（默认 50，最大 1000） |

**POST /tasks 请求体：**

| 字段           | 类型                                                                                                        | 状态 | 描述     |
| -------------- | ----------------------------------------------------------------------------------------------------------- | ---- | -------- |
| `title`        | string                                                                                                      | 必填 | 任务标题 |
| `projectId`    | string                                                                                                      | 必填 | 项目 ID  |
| 其他允许的字段 | `notes`、`isDone`、`timeEstimate`、`timeSpent`、`projectId`、`tagIds`、`dueDay`、`dueWithTime`、`plannedAt` |

**PATCH /tasks/:id —— 受限字段：**

`parentId` 和 `subTaskIds` 不能通过 `PATCH` 设置（返回 400 `UNSUPPORTED_FIELD`）。此 API 不支持重新设置现有任务的父任务；请改用删除并重新创建的方式。

## 4. 版本控制与兼容性

### 模式版本控制（同步）

- **当前模式版本：** 1（`packages/shared-schema` 中的共享模式）。
- **最低支持版本：** 1。
- **最大版本跳跃：** 3（如果远程数据比客户端早超过 3 个版本，客户端应更新）。
- 操作和快照携带 `schemaVersion`；服务器验证并可能拒绝不支持的版本。

### 向量时钟

同步使用向量时钟进行冲突解决。服务器验证/清理时钟：最多 50 个条目；键最多 255 个字符；值 0–100,000,000。无效条目会被剥离。

### API 验证（同步服务器）

- 操作 ID：1–255 个字符。客户端 ID：字母数字、下划线、连字符；最多 255 个字符。
- 实体类型：1–255 个字符。模式版本：1–100。
- 按操作类型（CRT、UPD、DEL、MOV、BATCH、SYNC_IMPORT 等）验证负载；参见 `sync.types.ts` 中的 `validatePayload`。

## 一般说明

- **同步服务器：** 面向生产（JWT、速率限制、CORS、Helmet）。多实例部署有局限性（例如通行密钥挑战存储在内存中；快照生成锁）；单实例是典型部署方式。
