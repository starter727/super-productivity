# 重复任务（Repeating Tasks）

Super Productivity 中的重复任务是按计划重复的任务——每日、每周、每月或每年——这样你无需反复创建同一任务。应用存储一个**重复配置（repeat configuration）**来定义模式，然后在其到期时自动创建新的任务实例。理解重复任务如何定义、下一个实例何时创建，以及应用如何避免重复和处理跳过日期，有助于你在规划器、日程和今日视图中可靠地使用它们。

关于如何在 UI 中创建、编辑和管理重复任务，参见 [[2.06-Manage-Repeating-Tasks]]。关于重复配置如何融入任务模型，参见 [[4.09-Task-Attributes]]。重复任务不能变为子任务；参见 [[4.11-Subtasks]]。

## 重复任务如何定义和存储

重复任务由一个链接到任务的**重复配置**定义。配置单独存储，描述了模式。你可以设置的关键选项包括：

- **重复周期（Repeat cycle）** —— 任务重复的频率：每日、每周、每月或每年。
- **重复间隔（Repeat interval）** —— 实例之间的单位数量（例如"每 2 周"或"每 3 个月"）。
- **开始日期（Start date）** —— 模式开始的时间；应用不会在此日期之前创建实例。
- **最后创建的实例（Last created instance）** —— 应用跟踪最近一次创建任务实例的日期，以便知道下一步创建什么。
- **跳过的日期（Skipped dates）** —— 你可以将特定日期标记为"跳过"，以便在这些日期不创建实例；模式在前后继续。这让你可以跳过假日、休息日或一次性例外，而无需更改规则。
- **开始时间和提醒** —— 可选：每个实例的默认时间（和提醒），使重复工作以固定时间出现在日程上。
- **子任务模板** —— 可选：一组添加到每个新实例的子任务，这样你无需每次都重新创建相同的清单。

应用还提供了映射到常见模式的**快速设置**——例如"每天"、"每周此工作日"、"每月此日期"、"仅工作日"（周一至周五）、"每年此日期"或"自定义"以获得完全控制。这些是填充底层周期、间隔和（对于每周）哪些工作日的快捷方式。

当你使一个任务可重复时，它保留其项目、标签和其他属性；重复配置被添加，应用使用它来生成未来的实例。

## 什么触发下一个实例的创建

应用在检测到实例到期且尚不存在时创建**下一个任务实例**。它通过以下方式实现：

1. **查看模式** —— 从重复配置（周期、间隔、开始日期、最后创建的实例）中，应用计算出距离今天最近的_应该_已创建任务的日期（或从选定的"截止"日期向后推算）。这决定了哪些日期是"缺失的"并需要一个实例。
2. **检查每个候选日期** —— 对于每个这样的日期，应用检查该日期是否已存在实例（且该日期不在你的跳过日期列表中）。如果缺少实例，则创建一个。
3. **更新配置** —— 创建实例后，应用更新"最后创建的实例"，以便不会为同一日期再创建一个。这保持模式同步并避免重复。

当你**首次**使任务可重复时，应用根据模式和开始日期计算**首次出现**日期。它可以将任务的截止日期设置为该首次出现，并且如果首次出现不是今天，则将任务从今日列表中移除，以便它出现在正确的日期。这样第一个实例从开始就与重复规则对齐。

实例创建作为正常应用使用的一部分运行（例如当你打开应用或切换上下文时），因此当应用追赶进度时，逾期的实例会被创建。你无需手动触发创建，除非你的工作流暴露了"创建下一个实例"操作。

## 应用如何防止重复和处理例外

应用使用多种机制来避免重复实例，并确保同步和跳过日期的行为正确。

### 确定性任务 ID（Deterministic Task IDs）

每个重复实例使用从重复配置和日期推导出的**可预测 ID** 创建。这意味着相同的配置和相同的日期在每个设备上总是产生相同的任务 ID。当你同步（例如通过 WebDAV 或 Dropbox）时，两个都运行"为此日期创建实例"逻辑的设备将创建具有相同 ID 的任务，因此同步看到一个任务，而非两个。这防止了跨设备的重复。

### 创建前的重复检查

在创建指定日期的实例之前，应用：

1. **检查现有实例** —— 它查找已具有该重复实例相同 ID 的活动或已归档任务。如果找到，则不创建。
2. **检查跳过的日期** —— 如果该日期在你的跳过（已删除）实例列表中，应用不会为该日期创建任务。模式继续；该日期被简单跳过。
3. **更新"最后创建"** —— 成功创建后，应用更新配置的"最后创建的实例"，使下一次运行知道不再为该日期创建。

这些步骤共同确保每个重复配置的每个日期最多保留一个实例，无论在本地还是同步时。

### 跳过的日期（例外情况）

你可以在不更改重复规则的情况下**跳过特定的发生日期**。这些日期存储在配置的例外列表中。应用永远不会在这些日期上创建实例，但会为所有其他符合模式的日期创建实例。因此，你可以跳过某一天（或几天），而其余日程保持不变。

## 日程和规划器中的重复任务

**日程**视图可以在实际任务实例创建之前显示重复任务的**投影（projected）**实例（如果设置了开始时间）。这为你提供了前瞻性时间线：你可以看到下一次"站会"或"评审"将按照模式在何时发生。一旦实例被创建，它作为正常任务出现在日程上。参见 [[4.04-Schedule-View]]。

**规划器**视图也在重复任务将发生的日期显示其投影，因此你可以看到重复工作如何融入一周或一个月。参见 [[4.03-Planner-View]]。

重复模式的日期计算在内部使用一致的参考时间（正午），以避免时区和夏令时问题，因此"下一次出现"在不同时区和夏令时变化中保持正确。

## 总结

- 重复任务由一个**重复配置**定义（周期、间隔、开始日期、跳过日期、可选时间和子任务模板）。

- **确定性 ID**（配置 + 日期）防止跨设备同步时的重复实例。
- **跳过的日期**让你可以省略特定发生日期而不破坏模式。
- **日程**（和规划器）可以显示重复实例的投影；一旦创建，实际实例就会显示。

## 等待完成选项

当你在重复任务上启用**"等待完成"**时，应用直到你完成当前实例后才会创建下一个实例。这对于必须按顺序完成的任务很有用——例如，每周回顾应该只在你完成前一周的回顾后才出现，或者如果你落后了，重复的杂务不应该堆积起来。

### 工作原理

- **正常行为**：应用根据计划（例如每周一）创建下一个实例，无论你是否完成了前一个实例。
- **使用"等待完成"**：应用检查是否有任何未完成的实例存在（包括已归档的任务）。如果有，则不会创建下一个实例。一旦你将当前实例标记为完成，如果其计划的发生日期已经到期，则下一个到期实例会立即出现。

### 关键行为

- **完成后立即创建**：当你完成门控任务且下一个计划发生日期已经到期时，下一个实例会立即创建——你无需等到第二天或重新启动应用。
- **已归档实例计入**：如果你归档了一个未完成的实例，它仍然会阻止下一个实例的创建。这防止了在旧工作未完成时模式提前推进。
- **已完成阻塞任务被重新检查**：完成任何未完成的实时或已归档实例会重新检查是否可以创建下一个到期任务。如果其他未完成实例仍然存在，创建保持阻塞。

### 使用场景

- **顺序回顾**：仅在前一个回顾完成后才应出现的每周或每月回顾
- **不应堆积的杂务**：你想要完成一个后才出现下一个的重复维护任务
- **习惯追踪**：在移动到下一次发生之前确保完成的任务

此选项独立于"从完成日期开始重复"（它将计划重新锚定到完成日）。如果你希望任务在完成后 N 天重复**并且**等待完成后再创建下一个实例，你可以同时启用两者。
